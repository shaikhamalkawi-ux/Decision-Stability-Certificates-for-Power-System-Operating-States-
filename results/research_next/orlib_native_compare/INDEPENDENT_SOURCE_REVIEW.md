Requested changes before freezing this comparator:

1. The Q/R headroom implication currently uses `Q(pmax)-Q(pmin)`. The pinned Julia source and source-derived Python adapter first perform **binary64 subtraction**. Those are not equivalent for arbitrary input values. Use the exact rational of that rounded width, or the actual matched original row coefficient, for this proof. The current issue can cause a conservative false mismatch; it does not make the current implication a false equivalence certificate. No scientific evaluation was performed to determine whether the selected values expose it.
2. Preparation hashes original inputs, rereads captured payloads and later rehashes originals. Explicitly match each captured byte string's size/hash to its initial descriptor before writing and verify each copied payload against the same descriptor. This prevents an unbound captured version if a source changes between those reads. It is a transport fix, not a comparison change.

Final delta verification: the headroom proof now uses `Q(float(pmax)-float(pmin))`; each captured payload must match its admitted original size/hash, and each copied payload is read back and compared to those exact captured bytes. Parsed s1 and the default-read/repair flag are now checked explicitly. These fixes were reviewed without running comparison or preparation. The previous seven invented checks retain their original source receipt honestly; their tested helper routines were unchanged, and this reviewer did not rerun them.

Also recommended while still pre-freeze: compare parsed `scenario_name` with s1 and require `native_default_read_and_repair` true, rather than only requiring aliases to agree with an arbitrary parsed name. Exact nominal algebra is invariant to scenario renaming, but the broader claim of complete parsed agreement should reflect the pinned `read(String)` behavior.
