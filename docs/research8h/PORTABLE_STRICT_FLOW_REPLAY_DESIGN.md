# Design only: portable solver-free replay of strict flow-model evidence

This delivery-validation proposal adds a new entrypoint. It does not alter old portable wrappers, frozen manifests, science models or results. No implementation or execution is authorized by this document. The uncapped branch is eligible only after its producer closure and independent post-run PASS; otherwise the first implementation must explicitly exclude it, rather than describe pending evidence as verified.

## Fixed scope

The closed capped flow-conserving DC arm contributes exactly two full rational strict points (January identity and control26100200) and two exact negative certificates (ordinary26093200/01). Replay both selected separators and retain the parent records for all four predetermined ray candidates per target, including raw-sign rejection and nonseparating candidates. Verify strict gaps and the separately recorded exact binary64-tau expansion. Native and matrix membership of positive points is at tau=0.

If the independently closed strict-energy arm is included, add exactly three strict uncapped rational points, three exact objective lower bounds and two optimal-energy penalty intervals. Replay all retained fixed lower-bound candidates, their selected maxima/ties, sparse residuals and finite-box correction, not merely a stored bound value. Distinguish the full-relaxation lower models from fixed-schedule upper proposals. Preserve any NO_UPPER, incomplete bound or crossing-zero classification if present; never substitute another point or simplify the denominator. The two uncapped target schedules remain the predetermined inherited schedules, not newly searched schedules.

The capped and uncapped scopes together contain five full point checks, two selected negative proofs, three selected objective lower bounds and two interval calculations, plus the fixed rejected/nonselected candidate and historical ledgers. This is one known-case model-sensitivity result; the original independently rounded angle-model outputs and historical denominators remain unchanged.

## Proposed interface and portable dependencies

Proposed entrypoint: `reproducibility/replay_strict_flow.py --package-root PATH --report-dir NEW_EXTERNAL_PATH --expected-package-manifest-sha256 HASH --package-evidence-commit COMMIT`, run using a separately installed ordinary Python interpreter with `-I -S`. The manifest hash and evidence commit must come from independently frozen candidate provenance, not values asserted by the package itself. Use standard-library JSON/CSV/gzip/hashlib/zipfile/struct/Fraction and the hash-pinned reviewed NPZ kernel. No NumPy, SciPy, highspy, other third-party runtime, optimizer, internet, native CSV reconstruction or model assembly is allowed. Reuse the reviewed lossless rational point decoder and full-row checker only with pinned bytes and explicit portable path handling. The strict native check must retain separate capped and uncapped semantics; no failed cap check may be ignored to obtain uncapped acceptance.

The CLI report directory must be fresh, outside the package tree, and independent of the working directory. Resolve it canonically before any report write; reject package-contained report paths and existing report destinations. Enable no-bytecode mode before importing local helpers. All reports go to the external directory. The package may contain inherited bytecode, but the replay must create no new archive writes or caches. Do not claim a cache-free historical archive.

## Binding and path checks before mathematical replay

Start with a newly constructed candidate package's outer manifest, whose actual bytes must first match the separately supplied expected SHA256 and whose evidence commit must match the separately supplied fixed commit. Check exact member/file set, sizes, SHA256 hashes, unique normalized paths and archive/link safety. Reject absolute or parent-traversal members, duplicate canonical names, symlinks/reparse-point escapes and paths outside the resolved package root. Verify the fixed replay source/helpers/protocol themselves against the outer bindings before loading helper code. Preserve the downloaded/published original package unchanged; candidate assembly and its provenance must be separate and reviewable. A self-consistent package alone does not establish the trusted candidate binding.

Then verify the closed capped artifact inventory and its103-input manifest, and the eligible uncapped input/artifact manifests, including all historical source/schedule/native bindings they reference. Use one explicit frozen map from original workspace/native prefixes to package-relative roots, derived from the established native addendum. Do not guess paths from suffixes, ignore unmatched entries or rewrite old manifests. Multiple original bindings to one portable payload must agree exactly in size and hash. Verify the native addendum's inventory/license/attribution as packaged. If any required dependency is absent, fail with the exact missing logical path; do not silently access the original host filesystem or download it.

Model metadata may retain historical absolute paths as provenance, but replay must not follow them. All actual file reads use approved mapped or package-relative paths. Point/certificate model hashes must match the actual local model/bounds/objective/full-mask artifacts, so a certificate cannot be paired with a modified matrix.

## Exact mathematical and native replay

For each strict point, decode all29400 reduced rational coordinates with the existing bit/shape guards. Use the complete original12096-coordinate binary mask, not a U-only mask or a continuous mask. Recompute every original row and finite box at tau=0 and the exact23-fossil energy sum. Check every native availability, hydro and committed-output rule, canonical transition, mature initial/clipped residence, native on/on ramp, flow equation/limit and nodal incidence. Retain the original rationalization of the binary64 hourly ramp conversion. Angle bounds and the actual pinned bus remain in the complete model check. Capped cases enforce23195; uncapped cases must verify that the cap alone was deleted and is explicitly absent.

Verify the control's14-position source-hour permutation and exact P/theta/flow mapping, unchanged chronological canonical U/Y/Z and exact energy equality. This direct native replay is necessary even though the control preserves U. Compare all full-model cap-only deletion maps and fossil objectives needed to interpret uncapped objective bounds; do not reconstruct a new native model.

Recompute each selected Farkas gap from every exact matrix coefficient and actual finite row/column endpoint. Check all eight ray candidates' signs/projection recipes against the stored raw rays, retaining each rejection or nonseparating result. Recompute strict and expanded support identities separately. For objective bounds, form `r=c-A^T y`, the finite selected-row beta and `L=beta+min_box(r*x)` exactly. Replay all five retained lower candidates per model (fifteen total when present), and recompute candidate selection, sparse residuals and all three strict lower bounds without trusting numerical dual feasibility or optimizer status.

When all finite strict enclosures exist, verify L<=U, the exact difference interval `[L_t-U_i,U_t-L_i]`, its positivity flag and the stated percent interval only with L_i>0 and L_t>=0. The upper values are exact feasible energies, not claims of global optimum. Validate all case/hour denominators and actual call counts against closed records; the wrapper itself makes zero calls.

## Prospective review and relocation validation

Write and independently review the new source/protocol and focused orchestration/bound/path tests before execution. Bind a concrete candidate package that contains exactly the closed science inputs, helpers, source/protocol and applicable native provenance. Independently check candidate completeness before the single initial relocated replay. Extract to a fresh directory outside the worktree and run `-I -S` with a fresh external report directory. Record interpreter/version/platform, original/candidate package digests, actual runtime, results and before/after full package file-set/hash snapshots.

Preserve the first failed report if any and diagnose it explicitly; no success claim is permitted until a complete relocated run passes. Any corrected attempt must receive a new report directory and binding rather than overwrite failure history. No repeat is needed merely to obtain another successful timing. A local relocation is not execution on a second machine or an independent solver reproduction. Successful scope is offline verification of the exact archived mathematical evidence and available raw/native provenance in this separately specified flow-conserving DC model.
