# Codex Workflow

Codex is authorized to update DSC-Grid when evidence supports a scientific revision.

## Operating rules

1. Start from the active V7 baseline supplied through the connected project workspace.
2. Do not modify or silently overwrite the baseline in place.
3. Preserve raw data, source URLs/query parameters, hashes, solver settings, logs, and environment provenance.
4. Distinguish exact optima, certified bounds, feasible witnesses, solver failures, and non-convergence.
5. Do not interpret solver non-convergence as infeasibility.
6. Do not introduce decorative methods, arbitrary robustness tests, fuzzy logic, or machine learning without a defined evidence-supported scientific purpose.
7. Use ADMIT / SUPPLEMENT ONLY / HOLD / REMOVE gates for new evidence.
8. If substantive new evidence is admitted, create the next sequential version and provide a V7→new-version changelog.
9. Return final packages both to the connected Google Drive project OUTBOX and as downloadable artifacts when the runtime permits.
10. Journal submission itself remains an author decision.

## Expected return package

A completed scientific revision should include the manuscript, source, supplementary research material, code, admitted data/acquisition records, numerical outputs, solver logs, environment lock, claim audit, clean-reproduction report, and SHA-256 manifest.
