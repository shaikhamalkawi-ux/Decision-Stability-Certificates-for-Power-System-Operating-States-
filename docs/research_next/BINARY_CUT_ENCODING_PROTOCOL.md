## Exact inputs and deterministic encoding

`encode_binary_cut(coefficients, rhs, *, coordinates=None, full_dimension=None, origin=None, require_exclusion=True)` accepts an exact coefficient sequence over its explicit coordinates. Source coefficients and RHS must be exact `Fraction` or `int`; source floats and booleans are rejected. Coordinate IDs default to `0..len(coefficients)-1` or are explicitly supplied as increasing unique nonnegative integers. `full_dimension` defaults to the supplied coefficient count for dense inputs. For a sparse full-state row, the caller supplies `full_dimension=12096`. Every supplied coordinate, including every supplied exact zero, receives a source/scaled/encoded/error record. There is no numerical threshold or support selection in this helper.

The full dimension is 1 through 12,096; explicit coefficient count may be zero through that dimension. Every explicit coordinate must lie in `range(full_dimension)`. Stored/accumulated rational numerator and denominator sizes are at most 8,192 bits. The record includes `full_dimension` and `implicit_exact_zeros` as the count and deterministic complement of explicit coordinates. The caller must prove every omitted original coefficient exactly zero by complete original-row reconstruction, archive that provenance, and receive the separate final proof review. The helper cannot prove matrix-to-cut completeness. This is exact zero completion, never threshold dropping. A zero-length support is a constant row and receives no master-insertion admission.

For the original inequality `a*z >= b`, take `s=2**k`, where k is the smallest integer such that s is at least the largest nonzero `abs(a_j)`. Determine k from integer numerator/denominator bit lengths and exact integer comparisons, never logarithms or float conversion. Negative and positive exponents are supported. All-zero support uses exactly `k=0, s=1`. Archive k as an integer and s as an exact rational. The scale itself need not fit binary64: only the scaled numerical coefficients and endpoint must be representable under the following policy.

Form `alpha=a/s` and `beta=b/s` exactly. Round each alpha once to a Python IEEE binary64 float, including exact zeros. Let `e_j=encoded_j-alpha_j` exactly and `E=sum(min(e_j,0))`. Over the declared `[0,1]^n` box, every original-cut-feasible state satisfies `encoded*z >= beta+E`. This box implication also covers exact binary states.

Convert `beta+E` once to nearest binary64. If and only if exact comparison shows that result is too high, use one `nextafter` toward negative infinity. Require the resulting lower endpoint finite and no greater than the exact target. Record nearest value, whether the single step occurred, final encoded hex and exact error. The upper endpoint is positive infinity. No extra binary tau, extra row tolerance, alternative scale or retry is added.

Frozen finite policy: reject any nonzero exact coefficient or endpoint that rounds to zero, including a final downward endpoint that becomes zero; reject any nonfinite conversion or downward result. Permit finite nonzero subnormal values. Reject unsupported rational size/type/coordinate inputs. Exceptions carry a reason code and do not trigger another encoding attempt. The caller must preserve rejected inputs and errors as a null, rather than selecting a new scale. Bit guards apply to specified rational results and accumulations, not every temporary Python allocation.

## Validity versus origin exclusion

For a newly generated refinement, leave `require_exclusion=True` and provide one complete `full_dimension` exact binary origin, even when the coefficient support is sparse. The record is eligible for backend insertion only if the original exact row and requested encoded row both **strictly** exclude that origin. A sound but nonprogressing numerical row returns a distinct null disposition; it is not rescaled. Exact origins contain Python integers zero or one only. A support-restricted origin is rejected when its length does not equal the full dimension.

For a seed necessary row, explicitly set `require_exclusion=False`. No origin is required, and a provided origin may satisfy the row. Validity and backend readback are still required. This separates a seed's necessity from a refinement's progress and prevents accidental exclusion claims for seeds.

Constant rows always retain the scale-one record but receive a separate non-insertion disposition. A nonpositive constant RHS is nonrestricting; a positive constant RHS would require separate global-proof handling. Neither disposition is interpreted here as a master infeasibility proof or an operational conclusion.

The original scientific fractional consistency control belongs outside this helper and must be checked against the original exact necessary cut. It must not be supplied as a binary origin. This transport proof does not cover fractional coordinates outside `[0,1]`; the invented controls include an explicit counterexample.

## Actual-backend verification

`verify_actual_binary_cut(encoding, actual_coefficients, actual_lower, actual_upper)` is a pure verifier of a saved actual row. It neither imports nor calls the solver. The caller supplies every actual coefficient pair or a mapping and actual binary64 endpoints from its full backend readback. Duplicate or out-of-full-dimension coordinates, any **nonzero** coefficient outside the explicit exact source support, nonfinite coefficients/lower endpoints and any upper endpoint other than positive infinity are rejected. An explicitly returned zero on an implicit source-zero coordinate is allowed and recorded separately. Solver-specific infinity sentinels must first be interpreted by the caller's separately checked backend contract; arbitrary large finite values are not infinity here.

The verifier first reproduces the entire encoding record from its exact source fields. It completes omitted explicit coordinates with actual zero and retains all exact actual residuals, including omissions. Every other original coordinate has exact source zero by the caller's proof and actual zero by complete readback; its residual is exactly zero. With `actual_e=actual_a-alpha`, it proves

`actual_lower <= beta + sum(min(actual_e_j,0))`.

This check uses the actual row; recording that a solver removed a coefficient is not enough. If the inequality fails, the row is rejected without modifying it. A changed actual row can be valid if this independently checked implication holds; exact requested/actual coefficient equality is not presumed. An encoded source row already marked ineligible cannot be rescued by subsequent backend changes.

In refinement mode the verifier additionally requires strict origin exclusion by both the original exact row and the actual numerical row. In seed mode these progress requirements are absent. All results explicitly record validity domain, missing coordinates, exact actual correction/bound/slack, original/actual gaps when an origin exists, and the final admission status. No backend feasibility tolerance is treated as a proof of strict exclusion.
