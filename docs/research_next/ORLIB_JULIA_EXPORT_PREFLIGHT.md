## Lossless raw export and mapping

Use the cached JuMP backend and MOI attributes: `ListOfVariableIndices`, `ListOfConstraintTypesPresent`, `ListOfConstraintIndices{F,S}`, `ConstraintFunction`, `ConstraintSet`, `ObjectiveSense`, `ObjectiveFunctionType` and the corresponding typed `ObjectiveFunction`. Export all indices, function/set types, affine terms/constants, bound sides and the objective constant. Store every Float64 as its UInt64 hexadecimal bit pattern; round-trip decimal values may be an additional convenience, not the equality criterion. Variable-in-set constraints, including `ZeroOne`, belong in the export rather than being mistaken for ordinary sparse rows. Current official API documentation is informative; implementation must use the selected pinned MOI1.20.1 source and record its actual dependency hash. [MOI attributes at1.20.1](https://github.com/jump-dev/MathOptInterface.jl/blob/v1.20.1/src/attributes.jl), [JuMP backend description](https://jump.dev/JuMP.jl/stable/manual/models/#Backends).

Use native variable dictionaries and their keys to map semantic roles U/Y/Z/D/Q/R/S/C/F/N/mfg to backend indices. Names are diagnostics, not the sole identifier. Verify every native variable has exactly one declared role or is explicitly rejected; preserve scenario, generator, hour and segment/category indices. Expect960 original binary coordinates,2472 retained coordinates and240 extra mfg coordinates from source inspection; the actual exported counts must be measured, not forced to match these expectations.

**Enumerate every backend constraint, including unnamed and duplicate rows.** The native PWL implementation inserts `Q=sum(S)` inside its four-segment loop but overwrites the same dictionary entry. Iterating only the dictionary or named constraints would omit three rows per unit-hour. Match canonical row multisets with multiplicity, not unique signatures or dictionary keys. Empty initial-dwell rows and repeated headroom/startup rows also need explicit accounting. [Pinned PWL implementation](https://github.com/ANL-CEEESA/UnitCommitment.jl/blob/4f04f0dd6641b071fd7556346c3d7190c2ffdfe5/src/model/formulations/KnuOstWat2018/pwlcosts.jl).

## Comparison layers and admission criteria

1. **Raw inventory and binary mask:** retain the untouched official export, native bounds/infinities and all variable-in-set constraints. Check all960 U/Y/Z/D coordinates are native binaries, including the startup-category variables. Counts and row order alone do not establish equality.
2. **Declared projection:** inspect every raw objective/constraint term involving mfg. All240 must have zero cost, only their nonnegative bound and no active row occurrence. Only then omit them, with the exact lift mfg=0. Any other reference is a mismatch, not a removable nuisance.
3. **Nominal finite-box normalization:** document separately the adapter's added finite upper bounds on Q/R and fixed box N=0. Q/R bounds follow from their nonnegativity, headroom and U<=1; N=0 follows from the one-bus equality. Preserve native segment/C/F bounds. These are a nominal polyhedral-equivalence argument, not raw column-bound identity.
4. **Rows, objective and binary64 arithmetic:** map variables and compare every scalar-affine row as an exact rational expression of the exported binary64 terms/constants and set endpoints. Permit only recorded row/column reordering, row sign reversal with the corresponding bound swap, and the declared bound/projection changes. Preserve duplicate multiplicity and report any arithmetic reassociation or one-ULP difference. In particular inspect both initial ramp bounds, PWL width/slope arithmetic and objective coefficients. Do not round coefficients, silently recompute an endpoint to match Python, use a numerical equality tolerance or drop a mismatching row.
5. **Report separate outcomes:** raw serialization/index identity; variable/row mapping; bit-exact coefficient/bound equality after stated transformations; and nominal mathematical equivalence under the proved projection/boxes. A nominally equivalent encoding is not necessarily the same uniformly tau-expanded model. The adapter's extra bounds/normalization can change that expanded set. Even a successful nominal comparison does not transfer the already proved expanded cost intervals to an independently expanded native JuMP model without an additional inclusion argument.

Any unexplained coefficient, binary, initial-history, cost or row-multiplicity mismatch leaves full runtime equivalence unestablished. Save the mismatch list and unchanged raw export; never alter frozen Python inputs/results or retrospectively reclassify a failed equality as exact equality. A new sidecar can refine `NOT_TESTED` to the precisely attained test status after independent review. Identity-only equality does not automatically claim independent native exports of the other five archived models.
