# Reconstruct the RTS inputs without the legacy V3 directory

The new RTS chronology and residence-certificate scripts accept a small portable source directory. It can be rebuilt from this repository's published target CSVs, the included author model and eight hash-locked upstream files. The historical private/local V3 folder is **not required** by a reader.

From the repository root, in a Python environment with NumPy, pandas and SciPy:

```bash
python src/v8r1_prepare_rts_inputs.py
```

This creates `.work/v8r1_rts_inputs/` containing:

- `code/dscgrid_model.py`: the author-owned model copied from `src/rts_native_model.py`, restoring its original LF line endings if necessary.
- `raw/RTS-GMLC_v0.2.3/`: bus, branch and generator CSVs plus the Hydro, Load, PV, rooftop-PV and Wind hourly tables.
- `processed/`: exact byte copies of all eight published 41-coordinate target dispatch CSVs and reconstructed `timestamp,row` mappings.

All upstream downloads use the official `GridMod/RTS-GMLC` repository at commit `3ece0d3725c844056132393ee252b3083dd4eab4`, with normal HTTPS certificate verification. The script verifies every download against the admitted SHA-256 lock; failure stops preparation and is recorded. It never substitutes another revision or disables TLS. Existing files are reused only if their hashes match the same locked content; `--refresh` requests all eight downloads again.

The row mapping is generated by matching each published timestamp to the native load table's `Year,Month,Day,Period` tuple, where Period is hour+1. It does not rely on a manually guessed month offset. It does not reconstruct or invent old optimization objectives, network flows or commitment counts: the new summaries contain only the two fields consumed by the new scripts.

The author-side check additionally used `--baseline-v3 PATH` once, comparing all eight acquired raw-file hashes, model arrays, hourly availability/load/rooftop-PV arrays, target values and timestamp/row mappings against the original V3 baseline. Those results are recorded in `results/v8r1/rts_input_reconstruction.json`. Ordinary reproduction does not use that optional argument.

After preparation, the solver-free explanatory check is:

```bash
python src/v8r1_rts_residence_certificate.py --source-v3 .work/v8r1_rts_inputs --output results/v8r1/rts_certificate_reproduced
```

The seasonal feasibility driver can use the same directory; it additionally requires `highspy` for the stated HiGHS experiments:

```bash
python src/v8r1_rts_seasonal.py --source-v3 .work/v8r1_rts_inputs --output results/v8r1/rts_seasonal_reproduced --seconds 60
```

The preparer itself performs **no optimization and generates no new targets**. It does not download or reconstruct the full GB/PyPSA-GB network. Native RTS benchmark files retain their upstream licensing and citation requirements. The small data subset is acquired at setup time rather than inserted into the frozen public companion ZIP.
